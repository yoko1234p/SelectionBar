# SelectionBar 0.5.7: paste at an insertion point

A single click in a focused, accessible, editable non-secure field now offers the enabled native Paste actions when the clipboard contains a compatible type. The click must hit the focused element or its descendant; disabled ancestors in the action layout remain respected. This insertion-only toolbar does not launch extension population. Configured website exclusions are checked against the accessible browser URL; where a browser URL is unavailable and exclusions are enabled, automatic click presentation is suppressed. Standard paste can pass non-text types to the destination; plain paste requires text. The target application still decides which formats it accepts.

Standard copy, cut and paste use the system's current ASCII-capable keyboard layout for their command-key combinations. On the tested input method, using the previous mapping added Shift to Command-V; the new mapping generated Command-V without Shift and pasted successfully. This affects the three standard edit combinations, not arbitrary extension key combinations.

On the signed installed app, a synthetic, guarded cross-process mouse fixture clicked an editable text field and then the real Paste button, verified the inserted text, checked secure and read-only fields did not present Paste, and dragged a selection to verify Copy still appeared. Clipboard formats were restored with a change-count guard, and the live profile hash was unchanged. The regression suite passed 39 app-support and 133 core tests, including isolated pasteboard-type and extension-population checks. The test used simulated events, not a human-operated mouse; it did not cover every browser, application, clipboard format, or multi-display setup. Input fields that do not expose their editable state through Accessibility cannot use this automatic path.
